## Design

### Current and Target Design

**Current**: `utils.nix` enables Antigravity CLI and its MCP integration, while `mcp.nix` defines the shared registry consumed by configured clients. `agent-instructions.nix` writes the shared Markdown file to Codex and Gemini paths. OpenCode uses the project `AGENTS.md` and two repository guidance files through its `instructions` setting.

**Target**: Remove the Antigravity configuration and Gemini projections. Set `programs.codex.context` and `programs.opencode.context` to the same existing `agent-instructions.md` source inside their current Home Manager modules. Preserve OpenCode's project `instructions` list and Codex's MCP config merge activation. Replace tests that assert Codex/Gemini linked instruction files with assertions that read and compare each configured native context source, and assert Antigravity/Gemini are absent. Remove the now-unneeded `agent-instructions.nix` module and update the exact discovered-module list in `tests/unit.nix`.

### Decision Rationale

Home Manager's native context options own each client's expected global instruction file and accept a shared content path. Keeping the source Markdown avoids duplicating policy, while the existing per-client modules remain the correct configuration boundary. No extra client or package is introduced.

### Risks and Mitigations

- A locked Home Manager revision could lack a context option shown by the live option index; evaluate the pinned revision before declaring success.
- Replacing OpenCode's project instruction list would change repository behavior; retain that list while adding global context.
- Antigravity's MCP configuration is generated by its client integration from the shared registry; remove the integration and generated output while keeping the registry and Codex/OpenCode entries.
